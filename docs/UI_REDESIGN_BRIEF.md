# UI Redesign Brief

## Product Frame

This is not a general graphics editor. It is a paperwork assistant for repeating
the same PDF signing/filling task many times.

The core promise:

> Turn a prepared PDF template plus reusable values into a human-looking filled
> PDF with minimal repeated effort.

## Target Workflow

1. Template
   - Choose a PDF.
   - Detect FreeText annotations as fields.
   - Show detected fields in plain language.
2. Values
   - Load JSON or enter values manually.
   - Highlight missing values and unused values.
   - Allow saved presets for recurring reports.
3. Preview
   - Show the PDF page preview as the main canvas.
   - Let the user toggle boxes, select a field, and adjust placement.
   - Keep handwriting randomness on by default.
4. Export
   - Choose output path.
   - Export PDF.
   - Show clear success/failure and where the file went.

## Screen Priorities

- Main canvas: PDF preview.
- Left panel: workflow steps and field/value status.
- Right panel or drawer: selected field settings.
- Bottom bar: preview/export actions and validation messages.

## Keep Out Of The First Screen

- Font routing internals.
- Per-character tuning.
- Raw config values.
- Long help text.
- Historical notes.

These can exist, but as advanced dialogs.

## Suggested UI States

- Empty: "Choose a PDF template" plus recent/sample template options.
- Fields loaded: detected field list with missing-value count.
- Values loaded: validation summary and preview button enabled.
- Preview ready: canvas with selected field details.
- Exported: success state with output path and reopen/export again actions.

## Technical Constraints

- Current stack is Python + Tkinter/customtkinter.
- Core PDF library is PyMuPDF (`fitz`).
- Core image library is Pillow.
- Handwriting output is generated by `generate_text_image(...)`.
- FreeText annotation content is the field key.

## Design North Star

The app should feel like a calm form-production tool, not a font laboratory.
Advanced handwriting controls are valuable, but the default user should only
need to understand: template, values, preview, export.
